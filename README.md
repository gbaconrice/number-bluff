# ナンバーブラフ — visual-v3 / GRAVITY adapter

36枚のゲーム本体、カードと背景の演出、GRAVITY向けSDKアダプター・画面連携を含むソースです。SDK部分はユーザーがAI Studioから提供した仕様に基づく実装で、**実際のGRAVITYでの複数端末接続は未検証**です。模擬テスト成功を実機動作や完成の保証にはしません。

## 操作とゲーム

- 「ゲームをはじめる」→ホストとしてルーム作成→参加待ち。BOTは任意追加で、BOT専用スタートではありません。
- 「ルームに参加」→IDで既存ルームへ参加するだけ。参加画面に作成・練習の導線はありません。
- 人間の名前・画像はGRAVITYプロフィール、マスコットはBOT専用。画像がない場合は中立な人型表示です。
- ロビーは1〜8席、試合開始は人間＋BOT合計2〜8席。36枚デッキ、特殊4種、ライフ3、脱落・再戦・部屋内勝数を実装します。
- ホーム設定・動きの設定UIはありません。背景は自動演出し、OSの動き軽減を内部で尊重します。
- カード公開→特殊効果→加算→倍率→比較→勝敗を段階表示し、誰の宣言・チャレンジかを示します。勝敗確定前にライフ減少で結果を漏らしません。

## SDKと検証の境界

`AgentSDK` が読み込み時に存在すると `gravity-platform.js` が接続を初期化します。SDKが遅れて提供される環境では、提供完了後に `NumberBluffPlatform.start()` を呼びます。SDK接続モードでは接続失敗をローカルBOT戦で代替しません。SDKのない通常ブラウザのみ、ホスト1名・BOT0体のローカル待機ロビーを使用します。

ホストがルール・乱数・BOTを一元実行し、参加者は入力要求と表示を担当します。ホスト識別は提供仕様の `user_list[0]` を初回に固定する方式であり、**参加順が保証されるかは実機確認事項**です。プロフィールは自己情報・参加一覧の `portrait`、参加通知の `portait` を使用します。

GRAVITY時だけ上端74px／98pxの除外領域を適用します。試合の結果演出完了後に、各クライアントが親へ `gameOver` と数値スコアを試合ごとに一度送ります。通常のラウンド終了や中断では送りません。

ゲスト退出・タイムアウト時は勝利を付けず同じルームのロビーへ戻り、ホスト喪失時は進行を停止して理由を表示します。これらは模擬環境での実装であり、実端末のバックグラウンド復帰、SDKネイティブ退出・招待表示・受信解除は追加確認が必要です。

一斉配信の現在手札は通信解析で読めます。画面上は自分のカードを伏せますが、チート防止済みとはしません。山順と乱数は配信しません。永続セーブ・ランキングはなく、勝数はそのルームのメモリ内だけです。無料枠無制限の保証もありません。

詳細は [AI_STUDIO_HANDOFF.md](AI_STUDIO_HANDOFF.md)、[GRAVITY_ADAPTER.md](GRAVITY_ADAPTER.md)、不変のルールは [CORE_API.md](CORE_API.md) を参照してください。

## テスト・配布HTML

Node.js 18以上。単体・通信模擬テストに外部依存のインストールは不要です。

```sh
npm test
node tools/build-single-html.mjs
python3 -m http.server 8000
```

ビルダーは `index.html` に記載されたCSSと実行JavaScriptを順序どおりインライン化し、`ai-studio.html` を生成します。ゲーム、スケジューラー、背景・カード演出、画面、SDKアダプター、プラットフォーム連携を含み、外部JSの読み込みは残しません。画像・フォントは `https://tanabe0422.github.io/number-bluff/assets/` の絶対URLです。SDK提供のプロフィール画像だけは動的なHTTPS URLを使用します。

原本を編集し、テスト・再ビルド・ブラウザ確認を行ってください。単体テスト、ブラウザの表示・操作、模擬SDK接続、公開素材のHTTP配信、実GRAVITY接続は別工程です。素材来歴・ライセンスは `assets/provenance.json` と `assets/OFL-MochiyPopOne.txt` を参照してください。外部バックエンド、APIキー、新規サービス契約は使用していません。
