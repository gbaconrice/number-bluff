# ナンバーブラフ — visual-v3 / GRAVITY adapter

36枚のゲーム本体、カードと背景の演出、GRAVITY向けSDKアダプター・画面連携を含むソースです。SDK部分はユーザーがAI Studioから提供した仕様に基づく実装で、**実際のGRAVITYでの複数端末接続は未検証**です。模擬テスト成功を実機動作や完成の保証にはしません。

## 操作とゲーム

- 「ゲームをはじめる」→ホストとしてルーム作成→参加待ち。BOTは任意追加で、BOT専用スタートではありません。
- 「ルームに参加」→IDで既存ルームへ参加するだけ。参加画面に作成・練習の導線はありません。
- 人間の名前・画像はGRAVITYプロフィール、マスコットはBOT専用。画像がない場合は中立な人型表示です。
- ロビーは1〜8席、試合開始は人間＋BOT合計2〜8席。36枚デッキ、特殊4種、ライフ3、脱落・再戦・部屋内勝数を実装します。
- ランキング用の連勝は、試合開始時に人間が2人以上いる試合だけが対象です。BOT混在でも対象となります。人間1人＋BOT戦は既存の連勝を増やさず、負けてもリセットしません。中断も連勝へ影響しません。BOT自身は記録対象外です。
- ホームは画像ロゴ、イラスト、作成・参加、遊び方に絞ります。説明コピー、カード図鑑への独立ボタン、設定ボタンは置きません。共通見出しは白文字の日本語システムフォントに統一し、装飾的な背景・カードは維持します。
- 動きの設定UIはありません。雲・星・流れ星やカードの演出は自動で動き、OSの動き軽減を内部で尊重します。
- カード公開→特殊効果→加算→倍率→比較→勝敗を段階表示し、誰の宣言・チャレンジかを示します。勝敗確定前にライフ減少で結果を漏らしません。

追加の仮面ルールは今回の対象外です。

## 効果音と動く背景・カードの扱い

設定画面の整理時に効果音処理まで削除された不具合を修正し、`game-audio.js` に音声処理を分離しています。設定画面は作らず、ホームと対戦ヘッダーの小さな音オン／オフボタンだけを置きます。選択は専用のlocalStorageキーへ保存し、古い設定キーには依存しません。配布・宣言・カード公開・特殊効果・加算・比較・勝敗に短い合成音を合わせます。音声素材の外部ダウンロードやBGMループはありません。

Web Audioは端末上の実際のタップ・キー操作で初期化・再開します。初回・復帰の非同期resume中は直近の1音だけ最大250ms保持して再開後に鳴らし、期限切れ・ミュート・非表示・退出時には破棄します。端末側が再生を拒否した場合は後の実操作で再開を試みます。非表示・停止中に鳴らせなかった過去の音を後からまとめて再生しません。公開済みの状態遷移と結果演出を音の起点とし、重複snapshotで宣言音を繰り返したり、通常の再描画で鳴っている宣言音を切ったりしない設計です。音は非公開カードの情報や将来の結果を利用しません。

実際のiOS・GRAVITY WebViewでの可聴出力と端末音量・消音設定の影響は未検証です。音声の単体テストやブラウザ内の音声ノード計測を、実端末で聞こえることの証明とは扱いません。

背景は、元の空のイラストを奥景、逆方向に流れる2層の雲を中景・前景として分け、星と流星を重ねています。カードや文字の位置は動かしません。背景の移動領域は画面外まで広げてクリップし、端の隙間や横スクロールを防ぎます。非表示タブでは停止し、OSの動き軽減指定では静止表示にします。

特殊4種の元画像は維持し、原画と同じピクセル位置の画像を使い、描かれたモチーフ内だけに異なる速度の反射・浅い陰影・金属の照り返しを重ねます。別の輪郭線は描きません。独立した渦・外周halo・拡散波・放射光は使用しません。汗風の白線・原画の複製揺れ・猫の呼吸・無関係な装飾カード周回は使用しません。通常11枚は白帯のみで、キャラクター・背景原画・枠・数字を浮遊させません。旧WebGL表面処理は廃止し、裏面/非表示/動き抑制時は演出を停止します。

## SDKと検証の境界

`AgentSDK` が読み込み時に存在すると `gravity-platform.js` が接続を初期化します。SDKが遅れて提供される環境では、提供完了後に `NumberBluffPlatform.start()` を呼びます。SDK接続モードでは接続失敗をローカルBOT戦で代替しません。SDKのない通常ブラウザのみ、ホスト1名・BOT0体のローカル待機ロビーを使用します。

ホストがルール・乱数・BOTを一元実行し、参加者は入力要求と表示を担当します。ホスト識別は提供仕様の `user_list[0]` を初回に固定する方式であり、**参加順が保証されるかは実機確認事項**です。プロフィールは自己情報・参加一覧の `portrait`、参加通知の `portait` を使用します。

GRAVITY時だけ上端74px／98pxの除外領域を適用します。提供仕様では `gameOver.score` がプラットフォームの個人最高記録へ送られ、ネイティブ結果画面がプレイを中断します。そのため各試合・再戦では送らず、本人が明示的に終了・退出する時だけ、本人の今回の最高連勝 `bestStreak` をプレイセッションにつき一度送ります。ホストが他人のスコアを代理送信することはありません。

ゲスト退出・タイムアウト時は勝利を付けず同じルームのロビーへ戻り、ホスト喪失時は進行を停止して理由を表示します。これらは模擬環境での実装であり、実端末のバックグラウンド復帰、SDKネイティブ退出・招待表示・受信解除は追加確認が必要です。

一斉配信の現在手札は通信解析で読めます。画面上は自分のカードを伏せますが、チート防止済みとはしません。山順と乱数は配信しません。アプリ独自の永続セーブ・ランキング画面・ランキングサーバーはありません。ルーム内の勝数・現在連勝・最高連勝はメモリ上で管理し、再戦では保持します。別途、提供仕様上のGRAVITY標準ランキングに最高連勝を送信します。ランキングを開くAPIは提供されておらず、ネイティブUIだけを使います。このランキング仕様も実機未検証で、無料枠無制限の保証はありません。

詳細は [AI_STUDIO_HANDOFF.md](AI_STUDIO_HANDOFF.md)、[GRAVITY_ADAPTER.md](GRAVITY_ADAPTER.md)、不変のルールは [CORE_API.md](CORE_API.md) を参照してください。

## テスト・配布HTML

Node.js 18以上。単体・通信模擬テストに外部依存のインストールは不要です。

```sh
npm test
node tools/build-single-html.mjs
python3 -m http.server 8000
```

ビルダーは `index.html` に記載されたCSSと実行JavaScriptを順序どおりインライン化し、`ai-studio.html` を生成します。ゲーム、スケジューラー、背景・カード演出、画面、SDKアダプター、プラットフォーム連携を含み、外部JSの読み込みは残しません。画像は `https://tanabe0422.github.io/number-bluff/assets/` の絶対URLです。SDK提供のプロフィール画像だけは動的なHTTPS URLを使用します。

原本を編集し、テスト・再ビルド・ブラウザ確認を行ってください。単体テスト、ブラウザの表示・操作、模擬SDK接続、公開素材のHTTP配信、実GRAVITY接続は別工程です。素材来歴は `assets/provenance.json` を参照してください。文字はシステムフォントを使用し、外部フォントは配布しません。外部バックエンド、APIキー、新規サービス契約は使用していません。

宣言は初手も含めて1以上の整数です。0は宣言できません（カードの0や負数、負の合計とは別です）。根拠：ニューゲームズオーダー公式ルールの紙面4ページ。
次ラウンドは敗者が残っていれば敗者から、敗者が脱落した場合はそのラウンドの勝者から始めます（同公式ルール紙面5ページ）。

## カード原画とコンポーネント演出

通常11種は柔らかな輪郭とパステル調の独立した原画です。`card-art.js` / `card-art.css` が値と `card-normal-*.webp` を対応させ、全カードの紙面・画像表示面を2:3に統一します。原画の上下は同じ縦横比のまま残し、数字背景の中央帯だけを静的に延長して異なる元画像比率を吸収します。キャラクターや特殊モチーフは変形・見切れさせません。数字領域は上部12〜38%。以前のDraft用の紫金風景11枚はこの候補には含めません。

特殊4種は `card-double.webp` / `card-extra.webp` / `card-max0.webp` / `card-reset.webp` の元画像をバイト一致で維持します。特殊のみ原画の位置に合わせたSVG演出が、表示中は操作なしで繰り返し動きます。`special-effects-controller.js` は計算phase・詳細表示の有限強調だけを制御します。通常・特殊とも白い斜め帯のキラ加工は廃止しています。非表示・画面外・閉じたダイアログ・OSの動き軽減中は停止し、再表示時は再開します。汗に見える白線、原画の複製揺れ、無関係な周回装飾は使用しません。旧WebGL表面rendererと通常の空texture移流は廃止し、通常カードの常時演出はありません（配布・公開時の既存演出は維持）。

通常キャラの反復グリッドは撤去。キャラクター自体は静止し、配布・公開済カードのflip・段階合計・効果音、周期的な控えめな白帯と有限の金縁、本人の優勝確定時だけの祝福演出を使用します。ライセンス全文はsingle HTMLにも収録。詳細は `COMPONENT_MOTION.md`。

homeは四体の構成を維持し、兎を通常soft原画と同じ前足2本・肉球のある後足2本へ統一した候補です。兎BOTも同じ足構造へ統一し、他3体のBOTは変更していません。既存のTOP/背景の動きは維持。裏向き・脱落カードに原画URLや値属性を生成しません。

単体テストを絵や演出の品質保証にせず、通常11原画・特殊4枚・小画面を実PNGで検品します。iOS・GRAVITY実機確認は別工程です。この改修の統合・配信確認は別工程であり、文書記載だけで公開済みとは扱いません。

遊び方は説明と無関係なBOT立ち絵を置かず、`guide-diagrams.js` / `guide-diagrams.css` の小図で、自分だけ裏向き・宣言の増加・予想に基づく挑戦・宣言と実合計の比較・ライフ減少を示します。元のルール文は変更せず、同値なら疑った側が負ける点も図示します。図は段落下の通常フローに配置し、小画面の本文や数字に重ねません。

## オンライン手番期限

オンライン・ローカルBOT練習ともに人間の手番は30秒。残り10秒から小さな残秒表示の色が変わります。入力中の値は送信せず、時間切れはホストが前の宣言＋1（初手1）を一度だけ確定します。BOTの思考時間は変更しません。ローカル練習では端末内で同じ最小宣言を確定します。遊び方表示中でも期限は進み、バックグラウンド復帰時には期限を再確認します。

期限はホストが手番トークン（セッション・試合・ラウンド・手番・履歴位置）と共に管理。再同期・プロフィール更新では延長しません。手動入力もホスト到着時点で期限確認し、期限以上なら自動宣言を優先します。ゲストの残秒は送信されたホスト時刻との差から表示する目安で、通信遅延はあり得ます。バックグラウンド停止中のタイマー実行は保証せず、復帰・受信・再同期時に期限を確認します。既存のホスト切断停止／参加者退出による無勝敗中断を維持します。

開発上の境界：最大安全整数の宣言後は有効な＋1を作れないため、時間切れ時は勝敗・連勝を付けずロビーへ戻します（自動チャレンジや数値オーバーフローはしません）。実GRAVITY上の遅延・バックグラウンド挙動は未検証です。

### ラウンド結果の自動進行
計算・公開演出の標準再生時間を確保した後、10秒で次のラウンドへ進みます。オンラインはホストだけが期限を管理し、手動の「次へ」もホスト限定です。ゲストは残秒を表示するだけです。ホストが演出を早送りしても共有の自動期限は短縮しません。ローカルBOT練習も同じです。優勝結果（試合終了）では自動再戦しません。背景タブではタイマー実行が遅れるため、復帰・再同期時にも期限を判定します。
